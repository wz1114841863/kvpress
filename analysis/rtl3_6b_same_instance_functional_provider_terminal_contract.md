# RTL3.6-B — same-instance functional provider / R4 terminal composition

**Status:** `completed_testbench_only_static_functional_provider_terminal_composition`.

RTL3.6-B closes one specific gap retained by the historical RTL3.6 no-PASS:
in one Chisel instance, four exact packed-source partial packets generated by
the existing Python RTL3.5-B functional provider are structurally accepted by
R4; their static RTL3.4-B functional-oracle terminal bytes then traverse the
real R4 -> R6 terminal association and existing same-child R5 durable reclaim
to `retire_ack`.

## Bound composition

```text
R3 pack_read / publication
  -> explicit verification-only packed-to-S2 association
  -> existing S2 fill verification ingress / READY
  -> testbench-only static packed fixture provider
  -> RouteASourceServicePacketAdapter
  -> RouteAMergeBoundary structural acceptance
  -> testbench-only static R4 functional-oracle terminal fixture
  -> existing R6 four-consumer terminal / retirement
  -> same R5 durable invalidation / reclaim
  -> retire_ack
```

`rtl3_6b_functional_provider_terminal.fixture` is a versioned, line-oriented
cross-language fixture. Python computes one packed-source `(m,l,o)` packet
for each of four legal GQA consumers and evaluates the accepted bytes through
the existing functional R4 oracle. The test-only Chisel bridge replays only
those immutable words. It waits until all four exact packet observations have
crossed `RouteAMergeBoundary` before offering the matching success terminal.
A mismatched identity, source instance, header, value payload, duplicate
consumer packet, wrong source-presence, or stale active merge cannot produce
that terminal.

The zero normalized-result word is intentional: the fixture uses a zero V
vector, while nontrivial Q/K values still exercise a present packed packet and
the canonical source/consumer/header/fragment association. The 4,096-bit width
is supplied by the frozen interface, so the resource uses width-inferred
Chisel literal `0`.

## What this closes

- One same-instance witness reaches `retire_ack` without the test driver
  manually injecting `packedOffer`, `packedFragment`, or `resultStub`.
- The bridge consumes R4's *accepted-packet* egress; it does not observe a
  source-plan copy or manufacture a terminal before structural acceptance.
- The existing source-packet adapter, R4 boundary, R6 four-consumer handling,
  retirement association, and same R5 reclaim child retain their unique
  owners. The top gains no owner or authority path.
- The preserved manual-stub witness still passes; fixture mode drives the
  legacy manual ingress `ready` low, preventing a bypass in that elaboration.

## Explicit limits

This is **testbench-only static fixture composition**, not live Python/Chisel
co-simulation, a production top, synthesizable attention/R4 numeric hardware,
or proof that a source storage owner computes partials. It does not close:

1. RTL3.2's explicit S2 sidecar/read transport verification ingress;
2. full reset-epoch composition across the live functional path;
3. HBM/SRAM/controller realization, MAC/RoPE/exp/FP implementation, timing,
   throughput, deadlock, area, energy, PPA, model/GPU, or A4 DSE claims.

The historical RTL3.6 no-PASS record is preserved. RTL3.6-B removes only its
provider/terminal same-instance blocker; it does not promote RTL3 functional
realization to complete.
